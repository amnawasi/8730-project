# AI Prompt Log

**Tool used:** Claude (Anthropic)
**Course requirement:** Per BSMM-8730 guidelines, this log documents the prompts used with AI tools during this project. All factual claims in the final report are independently verified against primary sources (Toronto Open Data, ECCC, official TTC documentation). Claude was not used as a source of factual information — only as an assistant for data engineering, debugging, and drafting. Below are the prompts that materially shaped the project's direction or caught real issues; routine step-by-step requests and acknowledgments are omitted.

---

1. **"Okay tell me from where i can get the data? Professor has strictly asked us to not to use kaggle."** — Established the constraint governing all subsequent data source decisions.

2. **"We are planning to shift to a new topic. The previous one is not giving us reliable data. Please see this proposal and let me know if its fine."** — The decision point to pivot from the original job-postings topic to the TTC transit delay analysis.

3. **"How confident are you that you will be able to establish a relationship between weather patterns and TCC delays?"** — Sanity-checked the core analytical premise before committing to the final proposal.

4. **Flagged that `extract_ttc_delays.py` only pulled subway data, not streetcar or bus**, despite the proposal's core premise being a three-network comparison — caught before it could compromise the whole analysis.

5. **Reported streetcar (~70%) and bus (~58%) `delay_category` uncategorized rates as unexpectedly high** rather than accepting them, which led to sourcing TTC's official code documentation instead of relying on guesswork.

6. **Reported `delays: inserted 193,427 rows (155,931 skipped for missing date)`** as a discrepancy worth investigating — this caught a mixed-date-format bug that was silently dropping ~45% of all delay records.

7. **Flagged that the cross-factor ranking table was missing a weather/snow comparison entirely**, which led to discovering the ECCC weather station in use had zero snow-depth records for the whole date range, and switching to the correct station (Toronto Pearson).

8. **"One thing, this time for visualisation i don't only need charts like these i want more analysis and visualisation that could back the strong evidences... whatever you think could be added to make my analysis and visualisation strong because the report laids on this."** — Expanded the visualization scope to include statistical correlation analysis (Pearson's r), not just bucketed comparisons.

9. **Flagged that `chart_temporal_vs_delays.png`'s legend only displayed "subway"** despite all three networks being plotted, and later flagged overlapping labels/captions on two other charts — caught before these went into the final report.

10. **"Just do a sanity check and keep going."** — Required every statistic in the drafted report sections to be verified against actual tool output before being written up, rather than trusted from memory.

---

## Summary of How AI Was Used

Claude was used for: structuring and debugging the Python ETL pipeline; diagnosing real data quality issues (mixed date formats causing silent data loss, a weather station missing snow measurements, a mislabeled "retired" dataset that was still live, SQL driver escaping bugs); building diagnostic SQL queries and visualizations; and drafting report sections from verified, actual analysis output. All statistics, correlations, and percentages in the final report were generated by code run against the real project database and cross-checked against tool output before inclusion — not generated or estimated by the AI directly.
